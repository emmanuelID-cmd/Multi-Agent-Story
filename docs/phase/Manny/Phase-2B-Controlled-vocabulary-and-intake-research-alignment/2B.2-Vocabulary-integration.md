# Manny Phase 2B.2: Vocabulary integration

Owner: Manny
Status: COMPLETE within the documented code/synthetic scope on October 28, 2026; live application acceptance is recorded separately in 2B.5.

## Prerequisites

- Phase 2B.1 has verified authoritative source access and documented response shape and limits.
- The requirements distinguish Library of Congress Genre/Form Terms (LCGFT) from Library of Congress Subject Headings (LCSH).
- `src/server/research/` and the existing intake contract boundary are inspected before implementation. The approved implementation creates `src/server/research/lc-vocabulary.ts`; its release verdict remains pending review.

## Steps

1. Propose or implement a small bounded server-side Library of Congress vocabulary client with caching, respecting the approved request bound.
2. Keep LCGFT genre/form terms separate from LCSH subjects; retain authority identifiers, source provenance and freshness.
3. Validate malformed records and handle timeout, unavailable-source, and cached responses explicitly.
4. Add synthetic tests for valid and malformed records, timeout, unavailable access and cache behavior.
5. Do not create substitute or invented fallback labels when authority data is absent.

## Acceptance checklist

- [x] Genre/form and subject data remain distinct and are represented using verified source values.
- [x] Authority IDs, source provenance, retrieval/freshness information and unavailable status are explicit.
- [x] Request and cache behavior are bounded and observable.
- [x] Synthetic tests cover valid, malformed, timeout, unavailable and cache cases.
- [x] No invented fallback vocabulary is returned as authoritative data.

## Out of scope

- Live requests beyond Phase 2B.1's approved limit.
- Claude-based term generation, broad crawling, or expansion to other vocabularies.
- User-facing intake changes, Gutendex mapping, or changes to Justin's Bible planner.
