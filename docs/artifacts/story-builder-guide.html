Build for

  • Adult fiction writers using AI for short, chaptered drafts.
  • Editors reviewing exported work and specific critique notes.
  • Evaluators comparing a bounded multi-agent run with a single-agent baseline.

Keep outside the MVP

Full novels, shared editing accounts, autonomous publishing or messaging, sales predictions, copyrighted full-text ingestion, author-style imitation, and autonomous changes to approved facts.

The story has checkpoints

Follow the product workflow in order. Approval and validation gates are application responsibilities, not decisions a model can grant itself.

PRD §3 / R01–R19

Proposed execution envelope

  • 3 concurrent model tasks
  • 1 retry per failed task
  • 120-second task timeout
  • 60,000 total model tokens per run
  • USD 3 provider-cost ceiling per run
  • Default critique threshold: 4/5 on available dimensions
  • Zero unresolved critical continuity issues at the critique threshold

When something goes wrong

  • Retry only the failed task from its saved input.
  • Preserve successful work; never duplicate chapters.
  • On cancellation, reject late results.
  • On budget limits, pause with saved outputs.
  • On research failure, offer story-only work.
  • Keep incomplete drafts and unresolved issues clearly labeled.
Concurrent prose needs shared contextAll chapter writers receive approved facts and relevant planned handoffs before dispatch. They cannot depend on another simultaneous writer's completed prose.

Shared responsibilities

Versioned schemas, task envelopes, fixtures, and integration boundaries. Neither assignment permits overwriting the other contributor's work or expanding a product agent's access.

Non-negotiable product rules

  • Approve a specific bible version before drafting.
  • Validate chapter indexes and versions before critique.
  • Keep fact IDs stable and approved versions immutable.
  • Enforce project ownership on every server operation.
  • Treat metadata, prose, and task outputs as data.
  • Keep secrets out of browsers, prompts, exports, and logs.

Design decisions & use

Primary users: Manny and Justin aligning before implementation. Primary task: locate a requirement, owner, or contract without switching documents. The highest-risk misunderstanding is treating a proposed safeguard as an implemented control.

Chunking groups the product, workflow, team, contracts, requirements, and source evidence. Familiar tabs support recognition; stable controls and shared tokens preserve continuity. Focus rings, large targets, semantic panels, and text status labels support keyboard use. On narrow screens the same tabs become a horizontal strip.

Everything loads locally with no API, account, telemetry, external font, or dependency. Search gives a count and a clear no-match state. Clear search and reset filters recover the view. A copy failure selects the schema tab and directs you to manual copying. JavaScript failure leaves a notice rather than implying the interactive content is available.

Trade-off: source documents use plain text to preserve their wording; the curated tabs provide the reading layout. Search is exact phrase matching, not semantic search. Source contents are an October 20, 2026 snapshot; update the artifact if the source documents change. Print shows all curated sections; Markdown download preserves all three sources.

Design reference: Laws of UX. Principles guide decisions; no user-research or accessibility-conformance result is claimed.
