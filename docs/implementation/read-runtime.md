# Executable READ verification harness

`scripts/read-harness.ts` executes the three READ runtime agents in a bounded local verification workflow. `npm run agents:read` uses an injected deterministic model and synthetic source/provider fixtures by default. It calls Research once, records a **synthetic coordinator fixture approval** bound to the exact dossier hash and brief/scope/criteria/dossier versions, then calls Reader on the existing synthetic three-chapter draft. It validates Reader's five-field handoff and source hashes before invoking Justin's existing `criticEditorA` and `criticEditorB` fixture functions. Consistency runs once for each editor's exact proposal ID, version, manuscript digest, and three-chapter snapshot. These editor functions are existing deterministic connectors; the harness does not claim a live Writer or Editor model ran.

The fixture uses an original Mara story passage and an original fictional harbor note. Both are labeled synthetic, with rights/locator/source metadata; no real historical fact or third-party prose is asserted. Its two confirmed dimensions cover a mystery clue and suspense technique in this scene; the harbor note is not requested as real historical evidence. Research cites exact eligible text for the genre and craft observations and retains a source attribution manifest with hashes and rights basis while omitting the full source text. Provider responses also use `example.invalid` and carry `SYNTHETIC_FIXTURE`. Research always returns `accepted: false`; the fixture approval record is only a test coordinator decision and never opens a real writer's planning gate. The final harness status is `verification_complete_awaiting_human` only after both Consistency checks return complete exact-version candidates. This status is verification evidence, not story, dossier, bible, or revision acceptance.

Run locally from the project root:

```powershell
npm.cmd run agents:read
npm.cmd run agents:read -- --fixture normal
npm.cmd run agents:trace -- --run <run-id> --agent research
npm.cmd run agents:trace -- --run <run-id> --agent reader
npm.cmd run agents:trace -- --run <run-id> --agent consistency
npm.cmd run agents:trace -- --run <run-id>
```

The trace command reads an existing run's logs and never dispatches another agent. `--follow` tails that same execution. The run creates a unique `.tools/agent-runs/<run-id>/` directory containing `events.jsonl`, one JSONL stream per READ agent, `manifest.json`, and `report.json`. A validated dossier candidate is saved as `dossier.json` before its synthetic approval hash is recorded, so the hash can be recomputed from the artifact. Both fixture and live-model modes save available `reader-handoff.json` and `consistency-manuscript_*.json` outputs, including partial candidates before gate evaluation; the report references these artifacts by relative path and semantic JSON SHA-256 hash. The report records statuses, reason codes, trace IDs, versions, source and proposal hashes, synthetic approval binding, fixture connector mode, and aggregate usage. Traces contain event metadata and codes, not source prose, model output, credentials, or private reasoning. Protected artifact files may contain quoted synthetic prose; they are separate from ordinary trace streams. The directory and files request owner-only permissions where the operating system supports them, and `.tools/` is ignored by Git. Trace viewers can be opened in separate PowerShell terminals without rerunning the harness.

`--live` changes only the model adapter to `claude-haiku-5-5`; the supplied story and eligible text remain synthetic fixtures, and provider results remain synthetic unless `--providers-live` is also passed. `--providers-live` calls the existing `readBookBenchmarks` adapter, which keeps its server-side `LIVE_BOOK_METADATA` and `BOOK_METADATA_TERMS_REVIEWED` gates; the harness does not enable them. Missing model credentials fail before dispatch. The live mode uses a shared 60,000-token, USD 0.25 estimate ceiling across all READ calls, including repair attempts. Failed calls retain their full reservation because billing may be uncertain. The configured USD 1 and USD 5 per million input/output token estimates are protective harness assumptions, not verified provider prices. A live run should be treated as a bounded smoke test, never as a calibrated quality or cost result.

The runtime enforces schema, owner/project/state version, chapter hash, source quote, source ID, model output, cancellation, timeout, retry, and per-task budget checks. The harness enforces the research and handoff barriers, both exact-proposal Consistency branches, and its aggregate budget. It does not add shared SQL persistence, application authorization, authenticated writer approval, or production coordinator recovery. Its single process owns the fixture state and writes a durable report; production acceptance must be bound atomically to current authenticated state by the shared application lane. A report with a blocked, failed, partial, or missing branch never counts as verification complete.

Research distinguishes blocking gaps in the requested evidence from nonblocking limitations about broader, unrequested claims. Reader receives its own source-preparation task separately from the downstream Editor assignment: located contradictions are findings to hand off, not missing source material. The protected artifact directory retains blocked dossiers and partial handoffs for inspection as well as successful candidates. Routine trace streams contain only event metadata.

## Verified local execution

The final unit suite passed **95/95** and TypeScript type checking passed. Live run `14b1dda7-4edc-45e1-a641-38db38a2e0f5` completed Research, Reader, and both exact-proposal Consistency checks with Anthropic `claude-haiku-5-5`. It used 8,415 input tokens and 7,676 output tokens across four successful model calls. The harness estimated USD 0.046795 using its protective rates; that is not a provider invoice. Its report is `.tools/agent-runs/14b1dda7-4edc-45e1-a641-38db38a2e0f5/report.json`.

The test story, book-provider responses, coordinator approval, and existing WRITE functions were synthetic. No live NYT/Gutendex data or real writer manuscript was processed. Earlier failed smoke runs remain in the same ignored run directory tree; they exposed API-schema compatibility, truncation, insufficient evidence, and task-boundary problems corrected before this successful run. One successful scenario demonstrates connectivity, not a measured reliability rate or production readiness.

`tests/read-runtime.test.ts` exercises the actual runtime with injected model and tool dependencies: successful two-dimension dossier and handoff candidates, missing-genre and exact-source rejection, source attribution hashes and rights basis without raw source text, unavailable required providers, unsupported quotations and bounded repair, Consistency identity/digest matching, cancellation of late and final-callback output, a forged authority object kept as source data, a source-ID collision, shared budget reservation, and the full synthetic connector path. The tests recompute the dossier and Consistency artifact hashes, check the recorded event streams, and ensure fixture prose does not enter ordinary traces. No external model or metadata provider call occurs in these tests.
